# Telegram-интеграция

Сайт связан с Telegram двумя способами:

1. **Автопостинг в канал** — новые одобренные события, места, занятия и лагеря публикуются постами в канал (`TELEGRAM_CHANNEL_ID`). Запускается кроном Vercel раз в день в 10:07 по Паттайе (см. `vercel.json`) или вручную: `npm run telegram:autopost`.
2. **Бот-помощник** — отвечает людям в личке подборками: `/today`, `/weekend`, `/soon`, `/places` (плюс кнопки). Сообщения приходят на вебхук `/api/telegram/webhook`.

3. **Уведомление автору предложения** — на экране «Спасибо» (и в окошке после «Дополнить карточку») есть тихая кнопка «Сообщить мне в Telegram, когда опубликуем». Она открывает бота (`telegram.me/<бот>?start=<токен>`), человек жмёт «Старт», бот сразу отвечает, что запомнил. Когда карточка из предложения стала видимой или дополнение принято, бот пишет автору одно сообщение со ссылкой. Отклонённым и дублям не пишет.

Данные оба берут из той же базы (Neon), что и сайт. Ссылки в постах ведут на страницы сайта.

| `src/services/telegram-autopost.service.ts`    | Логика автопостинга + журнал дублей               |

## Переменные окружения

Локально — в `.env` (без кавычек!), на Vercel — Settings → Environment Variables.

| Переменная                | Что это                                               | Где взять                                                   |
| ------------------------- | ----------------------------------------------------- | ----------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`      | Ключ от бота. Секрет!                                 | BotFather → `/mybots` → бот → API Token                     |
| `TELEGRAM_CHANNEL_ID`     | Куда постить                                          | `@pattayakidsguide`                                         |
| `TELEGRAM_WEBHOOK_SECRET` | Подпись, по которой вебхук отличает Telegram от чужих | генерирует установщик                                       |
| `CRON_SECRET`             | Пароль крона Vercel к autopost-endpoint               | генерирует установщик; Vercel сам шлёт его в запросах крона |
| `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` | Имя бота без `@` — для кнопки на экране «Спасибо». Нет переменной — кнопки нет | BotFather; на Vercel нужен Redeploy |
| `NEXT_PUBLIC_SITE_URL`    | Адрес сайта для ссылок в постах                       | напр. `https://<проект>.vercel.app`, без `/` в конце        |

## Команды

```bash
npm run telegram:test-post      # тестовый пост в канал (проверка токена и прав)
npm run telegram:baseline       # ОДИН РАЗ при подключении: пометить весь текущий
                                #   каталог (события, места, занятия) как «уже
                                #   опубликовано», без отправки
npm run telegram:reset          # показать, сколько записей журнала сбросилось бы
                                #   (ничего не удаляет)
npm run telegram:reset -- --yes # по-настоящему сбросить журнал; сузить по типу:
                                #   -- --yes --type=events,places,activities
npm run telegram:autopost:dry   # показать, что ушло бы в канал (без отправки)
npm run telegram:autopost       # опубликовать новое прямо сейчас
npm run telegram:webhook        # привязать вебхук бота к сайту (после деплоя)
```

## Первый запуск

1. Заведи в `.env` переменные из таблицы выше (токен бота — `TELEGRAM_BOT_TOKEN=...`; проверь `NEXT_PUBLIC_SITE_URL`).
2. Таблица журнала `TelegramPost` уже есть в схеме Prisma — отдельной установки не нужно.
3. `npx prisma db push` — создаст таблицу журнала в базе.
4. `npm run telegram:test-post` — в канале появится тестовый пост.
5. По желанию: `npm run telegram:baseline` — помечает ВЕСЬ текущий каталог (события, места и занятия) как «уже опубликовано», и канал начнёт с чистого листа. Если каталог пока маленький и хочется стартовых постов — пропусти этот шаг: автопостинг сам опубликует текущий контент (не больше 5 за прогон).
6. Закоммить и запушить изменения — Vercel задеплоит.
7. На Vercel добавь все 5 переменных (значения из `.env`) и сделай Redeploy.
8. `npm run telegram:webhook` — бот оживёт: напиши ему `/start`.

## Ежедневная жизнь

- Добавила события/места в базу → `npm run telegram:autopost` (или просто жди: крон опубликует утром в 10:07).
- За один прогон уходит максимум 5 постов — очередь дойдёт за следующие дни, канал не заспамится.
- Постятся только: события со статусом `APPROVED` и датой в будущем, места со статусом `APPROVED`, занятия и лагеря со своей страницей и «Видимостью: на сайте» (лагерь — пока не закончился). Демо-записи не постятся никогда.
- Очередь за один прогон: сначала события (ближайшие первыми), потом места, потом занятия — лагеря с ближайшим началом вперёд.

## Начать канал заново

Когда канал почистили руками и хочется, чтобы автопостинг опубликовал всё с нуля:

1. Посмотри, что будет: `npm run telegram:reset` — ничего не удаляет, печатает, сколько записей журнала сбросилось бы и сколько постов встало бы в очередь.
2. **Удали старые посты в канале руками в Telegram.** Сайт их не удаляет; если оставить, новые посты станут дублями.
3. Сбрось журнал: `npm run telegram:reset -- --yes`. Только часть — через `--type=events`, `--type=places`, `--type=activities` (можно несколько через запятую). Неизвестный тип — ошибка, ничего не удаляется.
4. Дальше автопостинг идёт как обычно: по 5 постов за прогон (крон раз в день или `npm run telegram:autopost`). Хочется проверить заранее — `npm run telegram:autopost:dry`.
5. Если нужен канал «с чистого листа» без стартовых постов — вместо шага 4 сделай `npm run telegram:baseline`.

## Уведомление автору предложения

Как устроено:

- При отправке формы сервер заводит у предложения **случайный токен** (`Submission.telegramToken`, 24 символа url-safe; не id предложения — id не секрет). Токен попадает в адрес экрана «Спасибо» (`?tg=…`) и в диплинк `https://telegram.me/<бот>?start=<токен>`. Только `telegram.me`, не `t.me`.
- Бот получает `/start <токен>`, находит предложение и записывает чат (`telegramChatId`). Токен одноразовый по смыслу: тот же чат повторно — «уже подключён», **другой** чат — отказ, перепривязать нельзя. Неверный токен — вежливый ответ на трёх языках.
- Язык ответов бота автору — `Submission.lang` (язык страницы, с которой отправили).
- Сообщение уходит из админки (`notifyAuthorsOfCard` / `notifySubmissionAuthor`) в момент, когда карточка видна, а статус предложения — «Опубликовано»; для дополнения — когда вы приняли фото. Отметка `telegramNotifiedAt` ставится до отправки: второй раз не уйдёт. Не принял Telegram — отметка снимается, баннер в админке предупредит, следующее сохранение повторит. Если человек заблокировал бота (403) — отметка остаётся, повторять нечего.
- Нужна колонка в базе: **`npx prisma db push`** (поля `telegramToken`, `telegramNotifiedAt`).

Проверка руками: коротко: отправить предложение на проде/превью, нажать кнопку на «Спасибо» → «Старт», опубликовать карточку в админке, получить сообщение.

## Если что-то не работает

- **401 Unauthorized** — неверный токен: проверь `TELEGRAM_BOT_TOKEN`.
- **403 / not enough rights** — бот не админ канала или без права «Публикация сообщений».
- **Бот молчит в личке** — проверь вебхук: `npm run telegram:webhook` покажет `last_error_message`; переменные на Vercel добавлены? был Redeploy?
- **Нет кнопки «Сообщить мне в Telegram» на «Спасибо»** — не задана `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` (или не было Redeploy), либо предложение отправлено до её добавления.
- **Автору не пришло сообщение** — он не нажал «Старт»; карточка скрыта или демо; предложение «Дубль/Отклонено»; сообщение уже уходило (`telegramNotifiedAt`). Баннер «не ушло» в админке — смотрите Vercel → Logs (`telegram: сообщение автору не отправлено`).
- **Пост без картинки** — `imageUrl` битый или файла нет в `public/`; пост уходит текстом (это осознанный fallback).
- **Дубль поста** — невозможен по журналу; если пост удалили из канала руками, повторно он не выйдет (запись в `TelegramPost` осталась).
