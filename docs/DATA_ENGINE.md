# Движок данных: откуда брать «скелет» места

«Скелет» места — название, адрес, координаты, часы работы, телефон, сайт.
**Уникальная ценность гида остаётся ручной** — описание в нашем тоне,
tri-state признаки (кондиционер, Wi-Fi, розетки…), советы «Полезно знать»,
цены и Thai-price, фото. Формула: автоматика ≈ 70 % скелета, человек ≈ 30 %
ценности — и эти 30 % и есть продукт.

## ⚠️ Данные Google Places хранить нельзя (решение 09.10.2026)

Импорт из Google Places API построен в июле 2026, но **записывать его
результат в базу нельзя** — это запрещают правила Google Maps Platform
(сверено с текстом правил 10.10.2026):

- [Terms of Service, п. 3.2.3](https://cloud.google.com/maps-platform/terms):
  (a) No Scraping — нельзя «pre-fetch, index, store, reshare, or rehost Google
  Maps Content outside the services»; (b) No Caching — кэшировать можно только
  то, что прямо разрешено в Service Specific Terms; (e) No Use With Non-Google
  Maps — нельзя «display or use Places content on a non-Google Map» (карта
  сайта — CARTO, не Google).
- [Service Specific Terms, п. 14 (Places API)](https://cloud.google.com/maps-platform/terms/maps-service-terms):
  координаты можно держать не дольше 30 дней; данные Places API нельзя
  использовать вместе с не-Google картой.
- [Places API policies](https://developers.google.com/maps/documentation/places/web-service/policies):
  бессрочно хранить можно только Place ID; показ без карты — с логотипом
  Google.

Что из этого следует:

- **`npm run import:place -- … --write` не использовать.** Команда копирует
  название, адрес, координаты, часы и контакты из Google в базу — ровно то,
  что запрещено. Нарушение грозит блокировкой ключа и платёжного аккаунта.
- **Нарушений не было.** Ключа `GOOGLE_PLACES_API_KEY` не появилось, запись ни
  разу не запускалась; все места каталога внесены руками по визитам, сайтам
  мест и звонкам.
- **Ссылки на Google Maps остаются.** `Place.googleMapsUrl` и поиск по адресу
  (`mapsSearchUrl`) — обычные ссылки, они открывают карту Google в новой
  вкладке; API и ключ для них не нужны.
- **Факты из первоисточника — свои.** Запрет касается копирования из API
  Google, а не самих фактов: часы и адрес, подтверждённые сайтом места,
  звонком или визитом, вносятся как обычно.
- **Google Place ID не нужен** (решение 09.10). Основной идентификатор места —
  свой; ссылка на карту хранится готовой. Единственная польза Place ID —
  регулярно спрашивать у Google «не закрылось ли место», а для этого нужны
  ключ и платёжный аккаунт. Поле `Place.googlePlaceId` остаётся пустым.
- Судьба самого скрипта (удалить или оставить только превью) — в
  [BACKLOG.md](BACKLOG.md), раздел «Техдолг».

На будущее: у Google есть Places UI Kit — готовый виджет, который правила
разрешают ставить рядом с не-Google картой (Service Specific Terms, п. 15).
Это живой показ данных Google, а не хранение, и он платный по просмотрам.

## Открытые базы мест: проверка 09–10.10.2026

Вопрос проверки: есть ли база, данные которой можно забирать без ключа и
карты и хранить у себя. Проверены три, каждая — выгрузкой по Паттайе и
сверкой с 7 местами каталога и 10 крупными аттракционами.

| | Overture Places | OpenStreetMap | Foursquare OS Places |
| --- | --- | --- | --- |
| Ключ, карта, регистрация | не нужны | не нужны | свежие релизы — только после регистрации (с 10.2025) |
| Хранить у себя, коммерческое использование | да | да, но share-alike | да |
| Мест каталога найдено (из 7) | 4 | 0 | 0 |
| Крупных аттракционов (из 10) | 10 | 9 | 10 |
| Телефон | ~72 % записей | ~10 % | ~10 % |
| Часы работы | нет в схеме | ~10 % | нет |

**Часы работы не даёт ни одна открытая база** — их знают только сами места.
Для гида это ключевое поле («открыто сейчас», утренний сценарий), так что
ручная часть работы никуда не девается.

### Overture Places — годится как список кандидатов

- Доступ: публичное хранилище, GeoParquet, релизы раз в месяц. Выгрузка
  Паттайи — около 30 секунд, 6 МБ, ~35 тыс. записей.
- Лицензия — по записи (`sources[].license`): Meta и Microsoft —
  CDLA-Permissive-2.0 (хранить, менять, смешивать со своими данными,
  зарабатывать; открывать свою базу не нужно); записи Foursquare (~1 %) —
  Apache-2.0 с обязательным NOTICE, их проще отфильтровать. Данных
  OpenStreetMap в теме places нет. При передаче самих данных дальше — приложить
  текст лицензии; на сайте достаточно строки «Источники данных».
- Слабые места: часов работы нет; признак «закрыто» пустой; из 7 мест каталога
  нет The Play Barn и обоих Skippy Land, а у двух найденных точка смещена на
  2–3 км; категории шумные (посёлки в «исторических местах», аквапарк в
  «парках»); встречаются дубли и места из других городов с ошибочной точкой в
  Паттайе.
- Автофильтр по детским категориям даёт ~340 записей, больше половины —
  мусор (сеть стейк-хаусов с тайским словом «ребёнок» в названии, приюты,
  бары), а часть нужного лежит в чужих категориях (Kidzoona — «park», Tiger
  Park — «cafe»). Полезный список получается только после ручного отбора.

**Что сделано 10.10.** Из выгрузки вручную отобран список из 118 кандидатов:
игровые и детские кафе, животные и фермы, аттракционы, занятия,
русскоязычные центры — с телефонами и ссылками для проверки. Список рабочий
и лежит локально, в репозиторий не кладётся (сырые данные Overture без текста
лицензии в публичный репозиторий не выкладывать).

**Вывод.** Для Паттайи скрипт в репозитории не нужен: разовая работа сделана.
Он понадобится при запуске второго города — тогда же стоит хранить
идентификатор записи Overture как внешний ключ, чтобы ежемесячные обновления
не предлагали одно и то же место повторно.

Как повторить выгрузку (DuckDB с расширением httpfs; рамку города брать с
запасом — нижняя граница 12.80 отрезает Ramayana, Aquaverse и Nong Nooch):

```sql
INSTALL httpfs; LOAD httpfs;
SET s3_region = 'us-west-2';

SELECT id, names.primary, taxonomy.primary, basic_category, confidence,
       websites, socials, phones, addresses, sources
FROM read_parquet(
  's3://overturemaps-us-west-2/release/<релиз>/theme=places/type=place/*.parquet')
WHERE bbox.xmin BETWEEN 100.85 AND 101.00
  AND bbox.ymin BETWEEN 12.70 AND 13.05;
```

Номер актуального релиза — в
[календаре релизов Overture](https://docs.overturemaps.org/release-calendar/);
лицензии — на странице
[Attribution and Licensing](https://docs.overturemaps.org/attribution/).

### OpenStreetMap — не подходит для скелета

- Детских центров, кафе и кружков в данных Паттайи почти нет; из 7 мест
  каталога не найдено ни одного.
- Лицензия ODbL требует share-alike: если смешать места из OSM со своими
  местами того же типа, таблицу этого типа придётся открыть (описания, цены и
  советы — нет). Подробно — в
  [Community Guidelines OSMF](https://osmfoundation.org/wiki/Licence/Community_Guidelines).
- Публичный Overpass API не рассчитан на регулярное коммерческое
  использование.
- Подложка карты сайта (CARTO на данных OSM) к этому не относится: атрибуция
  на карте уже стоит.

### Foursquare OS Places — не нужен

- Лицензия Apache-2.0 подходит, но с октября 2025 свежие релизы доступны
  только после регистрации; открытая копия — от февраля 2025.
- Из 7 мест каталога не найдено ни одного.
- Часть записей Foursquare уже входит в Overture.
- Платный Places API Foursquare хранить данные не разрешает — как и Google.

## Импорт из Google Places: как устроен (архив, запись не использовать)

Код остаётся в репозитории: `scripts/import/import-place.ts`,
`src/lib/import/`. Раздел описывает, как он задуман; **шаг записи запрещён
правилами Google — см. начало документа.**

### Конвейер

```
источник (Google Places) → черновик PENDING → проверка/дозаполнение → APPROVED
```

- Импортированное место создаётся со `status: PENDING` и `sourceType: IMPORT` —
  на сайт не попадает, пока не одобрено (публичные выборки видят только
  APPROVED).
- Дедуп двухслойный. Слой 1: `Place.googlePlaceId` (`@unique`) ловит повторный
  импорт того же заведения. Слой 2: у мест, занесённых вручную,
  `googlePlaceId` пуст — поэтому перед записью скрипт сверяет название (без
  регистра) и координаты (<150 м) с каталогом города и отказывается писать
  вероятный дубль (обход — осознанный `--force`).
- `npm run gaps` показывает, что осталось проверить, — включая непроверенные
  «В помещении/На улице» у импортов и черновики, ждущие одобрения.

### Ключ и команды

Ключ: <https://console.cloud.google.com> → проект → включить **Places API
(New)** → Credentials → API key → ограничить только Places API (New) →
`GOOGLE_PLACES_API_KEY=...` в `.env`. Нужен платёжный аккаунт с привязанной
картой.

```bash
# Поиск: текст ИЛИ ссылка на карточку Google Maps → список кандидатов
npm run import:place -- "Skippy Land Lotus North Pattaya"
npm run import:place -- "https://www.google.com/maps/place/…"

# Превью скелета выбранного кандидата (ничего не пишет)
npm run import:place -- --id=ChIJ…

# ⛔ Запись черновика в базу — НЕ ИСПОЛЬЗОВАТЬ (правила Google)
# npm run import:place -- --id=ChIJ… --write
```

Что скрипт не делает намеренно: не выдумывает описание, не мапит типы Google в
наши категории, не ставит tri-state признаки (они остаются `null` =
«уточняется»), не скачивает фото Google.

## Медиа-права (почему у фото есть source/rightsNote)

Авторское право на фото — у того, кто снял. Для семейного бренда это
репутационно критично, поэтому фиксируем провенанс каждого фото:

- `PlacePhoto.source`: `OWN` (снято нами) / `PLACE_OWNER` (прислано местом
  с его согласия) / `CONTRIBUTOR` (прислал родитель с согласием на
  публикацию); `null` — провенанс не зафиксирован (старые записи).
- `PlacePhoto.rightsNote` / `Place.imageRightsNote`: одна строка-основание —
  «свои фото (визит 2026-07-07)», «согласие владельца в LINE, дата».

Можно: свои фото; фото от самих мест с их «ок»; фото контрибьюторов с
согласием. Нельзя: чужие фото из Google/Instagram перезаливать к себе;
узнаваемые чужие дети без согласия — никогда.
